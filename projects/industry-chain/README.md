# 产业链指标与企业画像

将人工维护的产业链节点定义映射到企业，再计算节点关联、交易和企业基础属性，形成画像宽表及面向展示的数据表。

## 文件分类

| 目录 | 内容 |
|---|---|
| `code/` | 节点分类与企业映射、企业画像宽表两阶段主流程 |
| `utils/` | 环境配置、Stream Load、地区代码等实际依赖工具 |
| `delivery/` | 企业筛选、节点关系、节点强度、企业推荐和链路交易属性的 Python / SQL |

## 数据流程

```mermaid
flowchart LR
  A[人工维护的节点定义] --> B[节点分类与企业映射]
  B --> C[企业交易和关联指标]
  C --> D[工商与税务属性补充]
  D --> E[企业画像宽表]
  E --> F[企业筛选与链路交付表]
```

## 实现重点

面向数据分析岗位，优先阅读 `delivery/` 中的企业筛选、企业画像、节点强度和交易特征，再回看 `code/` 中的指标计算与属性补充。

1. 主脚本通过 `--industry` 和 `--year` 控制产业与统计年度。
2. 映射阶段按编码记录进度，画像阶段保留指标、补充属性和写入阶段的状态与缓存。
3. 数据查询和写入按批次组织；Stream Load 负责批量导入。
4. 交付层把企业、节点和链路指标转为具体的筛选与画像表。

## 运行边界与现有问题

核心代码选用 `交接/产业链相关_第一部分_数据开发`，与 `industry_chain_pipeline_v2` 中的两个主脚本内容一致。较早的 `代码优化` 目录是不同版本，没有同时混入。

运行需提供原流程要求的 Excel 字段、StarRocks 表结构及授权数据。`code/` 中两个主脚本已有命令行；`delivery/` 部分脚本和 SQL 仍使用固定产业、年份与表名，不能视为统一参数化入口。

配置优先使用进程环境变量。核心模块也可读取本目录下的 `.env`；变量示例见仓库根目录 `.env.example`。副本中的 Stream Load 认证与服务地址已使用现有 `get_stream_load_config()`。

原交接说明指出：最终写入没有按注释所述自动清空目标宽表，`row_key` 未包含 `chain_name`，扩展行业匹配分支的部分金额指标接近零。展示版保留原业务行为；运行或修改前须核对这些口径，不应宣称全链路幂等。

当前没有执行数据库集成测试，也没有进行真实数据性能对比。
