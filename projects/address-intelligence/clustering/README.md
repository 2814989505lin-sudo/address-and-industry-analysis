# 聚类方案对比

保留不同阶段的聚类实现，用于说明企业地址归并的方法选择。

| 文件 | 方法 | 阅读重点 |
|---|---|---|
| `clean_company_address.py` | 地址清洗 | 字符归一化及道路门牌截取 |
| `地址转经纬度和商圈（高德）.py` | 地图服务标签识别 | 地理编码和逆地理编码；属于地图标签映射 |
| `method2_geo_cluster.py` | HDBSCAN 地理聚类 | 经纬度输入、密度聚类与簇汇总 |
| `method2_memory_optimized.py` | 空间近邻查询与并查集 | cKDTree 半径查询、流式合并，以及其他聚类分支 |
| `method3_nlp_cluster.py` | 地址锚点与 embedding 图 | 地址锚点提取、近邻图和 Leiden 社区发现 |

## 方法取舍

- 地理路线依赖地理编码质量，适合研究空间上接近的企业。
- 当前 HDBSCAN 实现直接对经纬度使用欧氏距离，其距离单位是度；不能把阈值直接解释为米，也不应当作经过地理投影校正的实现。
- 语义路线利用地址文本及实体信息，不应将文本相似直接等同于实际地理相邻。
- 优化版中的平面换算使用固定米/度系数，具有区域假设；基于距离连通的并查集可能产生链式连接。
- cKDTree 与并查集减少保存全部邻接边的需要；本仓库没有经过实测的耗时、内存或准确率对比数字。
- 语义方案在筛选近邻前仍计算完整相似度矩阵，空间开销随样本数平方增长，尚未验证大规模数据表现。

这些脚本是实验入口，文件、阈值、模型和 API 配置仍需按具体任务调整。业务 Excel 和地理编码缓存均未收录。
