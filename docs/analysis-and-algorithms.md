# 分析与算法说明

以下说明依据候选包中的现有代码，不包含未经测试的效果数字。

## 1. 地址解析与异常处理

阅读 `projects/address-intelligence/hybrid-parser/address_parse_hybrid.py` 的 `parse_rule()`，以及 `excel-pipeline/1_address_parser_skeleton.py` 的字段识别逻辑。

规则阶段先归一化文本，再识别行政区划、道路、门牌、实体、楼层和房间等字段。疑难行由模型辅助处理。既有测试能验证部分规则和结果合并行为，不能代表真实地址全集上的准确率。

面试交流可围绕多房间号、实体名称混入道路、残余备注的保留等具体问题，解释为什么规则层和模型层需要各自的校验。

## 2. 位置相似度与地址归并

阅读 `projects/address-intelligence/database-pipeline/3_company_address_yuexiu_cluster.py` 的 `total_score()`、`can_link()` 和 `union_find()`。

当前数据库版本的基础位置分以 core 相似度和门牌分为主：双方存在道路且道路基名不同则基础分为零；门牌分可计算时，使用 core 和门牌的加权归一化；否则采用 core 相似度。基础分接近连边阈值时，允许通过实体名称相似度进行补充判断。

因此，这个版本不是简单地把 core、POI 和门牌统一加权。Excel 阶段的实现与它也不完全相同，应分版本解释。

最终使用并查集归并连通节点。连通分量允许链式连接：A 与 B 相似、B 与 C 相似，并不要求 A 与 C 同样相似。阈值选择及误合并问题需要通过标注样本验证，本次未做这样的效果评估。

## 3. 地理路线与语义路线

| 路线 | 现有实现 | 主要假设与限制 |
|---|---|---|
| 地图商圈标签 | 地理编码 + 逆地理编码 | 依赖地图服务的商圈定义与覆盖，属于外部标签映射 |
| HDBSCAN | 经纬度二维输入 + 欧氏距离 | 当前使用度为距离单位；地理尺度与参数解释需核对 |
| 空间连通聚类 | 固定米/度近似换算 + cKDTree + 并查集 | 区域近似、距离阈值、最小簇规模与链式连接影响结果 |
| 语义社区发现 | 地址锚点 + embedding + top-k 图 + Leiden | 文本相似不等于地理相邻；构图前完整相似度矩阵有平方空间开销 |

这些是不同方法的实现示例，仓库尚未提供统一数据集上的对照实验，不能直接得出某种方法效果最佳。

## 4. 商圈、空间和产业链画像

地址模块的 `sql/` 包含企业、商圈、楼宇和行业集群画像 SQL。产业链模块的 `delivery/` 包含企业筛选、企业画像、节点关系与强度、企业推荐以及交易特征。

面试展示时，建议按“业务问题 → 样本粒度 → 字段来源 → 指标口径 → 聚合或筛选规则 → 结果解释”阅读 SQL。需要区分企业粒度、节点粒度和商圈粒度，并说明各分值、阈值与缺失值处理的业务含义。

本次未连接数据库核验实际统计结果，也未建立准确率、召回率、聚类质量或耗时基线。个人负责的环节与真实项目成果应由项目所有者补充。
